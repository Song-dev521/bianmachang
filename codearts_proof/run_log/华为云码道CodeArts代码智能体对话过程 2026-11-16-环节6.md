案例① 思维链模型 max_tokens 过小返回空 content
- 现象：四路里某一路卡片空白，SSE 仍发 skill 事件，但 text 为空字符串；前端显示空卡片。日志显示 finish_reason=length（不确定！不要编造）。避免写 finish_reason。

### 2.1 用了什么能力

### 2.2 解决了什么具体问题

项目面向"直接双击运行"的使用者，原始环境有三类高频失败：

1. **Python 版本不一致**：pydantic v2 / FastAPI 0.110+ 在低于 3.10 的环境下导入即失败，报错信息对非开发人员不可读。脚本在安装前用 `sys.version_info >= (3, 10)` 显式拦截，并打印真实版本号。

3. **端口与编码问题**：8000 端口被占用时 uvicorn 直接失败；`.bat` 存成 GBK 会中文乱码，存成带 BOM 的 UTF-8 会让首行 `@echo off` 失效。脚本用 `chcp 65001`、UTF-8 无 BOM 保存，并在启动前用 `":8000 "`（带尾随空格）精确匹配本地地址列，避免把 80000 之类误判为占用。

## 六、遇到的问题与解决

### 6.1 案例一：思维链模型在 max_tokens 过小时返回空 content

**现象。** 四路评审中偶发某一路卡片正文为空。该路 SSE 事件正常推送、事件结构完整，但 `text` 字段是空字符串，前端渲染出一张只有标题、没有结论的空卡片；等级指标卡仍按空文本兜底显示为"中"。

**定位过程。** 先确认不是前端渲染问题：直接打印模型响应的 `message.content` 与 `message.reasoning_content`，发现 `reasoning_content` 有内容、`content` 为 `None` 或纯空白。再把 `MAX_TOKENS` 压到 512 做最小复现，空正文稳定出现；调到 2048 后恢复正常。由此确认不是 Prompt 或网络问题，而是输出预算被思考过程耗尽。

**原因。** `deepseek-v4.1-flash-1017` 是带思考过程的模型，`reasoning_content` 与最终 `content` 共享 `max_tokens` 预算。预算偏小时，思考过程先把额度用完，正式结论没有剩余空间，接口返回的 `content` 就是空的。这与普通对话模型的直觉不同——空正文不代表调用失败，HTTP 状态与响应结构都是正常的。

**修复。** 在 `providers.py` 的 `MaasProvider.complete()` 里做两层处理：

1. 输出预算默认值提高到 **2048**，并允许用环境变量 `MAX_TOKENS` 覆盖；
2. `content` 去空白后为空时，回退取 `reasoning_content`，避免前端拿到空白卡片；两者都为空则返回空字符串，由上层按异常路径处理，不伪造内容。

**验证。** 新增 3 个用例固定该行为：正文有内容时正常返回并去除首尾空白；正文为空、思考内容存在时回退思考内容；两者都为空时返回空字符串。另一个用例用 5 毫秒超时验证 `asyncio.wait_for` 的超时分支。54 个用例全部通过。

**遗留取舍。** 回退到思考内容只是"不显示空白"的兜底，思考文本不一定适合直接作为评审结论展示。目前依赖 2048 的默认预算保证正常路径不触发回退；若后续接入更复杂的 Prompt，需要重新评估预算，而不是继续依赖回退。

### 6.2 案例二：评审等级被褒义词误导，改按正文"位置："标记综合判定

**现象。** 同一段实际存在问题的代码，安全评审正文列出了"位置：第 12 行，存在可疑的 SQL 拼接"，架构评审正文也点名了职责耦合，但指标卡等级被判成 **low（低风险）**，页面呈现为绿色，与正文结论直接矛盾。反过来，也有"模型写了 `LEVEL: 低`，正文却列了具体问题位置"的情况。

**原因。** 早期 `parse_level` 只做关键词计数：正文里出现"结构清晰""可接受""无问题""低风险"等 low 关键词就加分，而模型在给出问题的同时常会先写一句"整体结构尚可""其余部分可接受"这类缓和表述。褒义词票数压过了问题描述，最终 `low` 得分最高。显式 `LEVEL` 行同样不可靠——模型可能把单条问题的等级写成整段结论的等级。

**修复。** 把单层关键词匹配改为三层综合判定（`providers.py:35-57`）：

1. **显式行加权**：匹配 `LEVEL / 等级 / 评级` 行（支持全角冒号与 `**` 加粗），命中档位 +3 分；
2. **关键词加权投票**：高、中、低三档关键词各计 2 分，取最高分；同分时按"高 > 中 > 低"偏向更严重的一档；
3. **位置标记兜底（关键改动）**：若最终结果是 `low`，但正文中出现至少 1 处 `位置：` 或 `位置:`，强制升为 `mid`。理由是"能定位到具体问题位置"本身就说明存在实质问题，不允许再评为低风险；没有任何等级信号时默认 `mid`，而不是乐观地默认 `low`。

**验证。** 用 4 个针对性用例锁定边界：显式"低"+ 位置标记 → `mid`；无等级行但含"位置：第 12 行" → `mid`；半角冒号"位置:"同样升级；显式"低"且正文确无问题位置 → 保持 `low`。配合原有的显式等级、关键词投票、同分偏严重、空输入默认值用例，`parse_level` 相关用例共 11 个。

**遗留取舍。** 这是一条规则启发式，不是语义判断。它能把"有具体问题却判低"的明显错误挡住，但无法区分问题的真实严重程度——位置标记只能保证"不为低"，不能自动升到"高"。因此等级只用于指标卡快速呈现，正文才是权威结论，这一条已写入 README 的"当前局限"。
