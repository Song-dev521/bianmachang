【安全评审结论】风险等级：**高**

【风险点清单】
- 位置：`sql = f"select * from user where name='{username}'"` / `cursor.execute(sql)`
  - 问题：使用 f-string 将用户输入直接拼接进 SQL 语句，构成典型 SQL 注入漏洞。
  - 危害：攻击者输入 `' OR '1'='1` 可绕过条件读取全表；输入 `'; DROP TABLE user; --` 可删除数据；结合 sqlite 特性还可能读取其他表，导致数据泄露或破坏。
  - 修改建议：改用参数化查询 `cursor.execute("select * from user where name = ?", (username,))`。
- 位置：`username = input(...)` 之后无任何输入校验
  - 问题：未对输入长度、字符集做约束。
  - 危害：超长输入造成内存/日志风险，特殊字符直接进入数据层。
  - 修改建议：增加白名单/长度校验，拒绝非法字符。
- 位置：`conn` / `cursor` 创建后未关闭
  - 问题：数据库连接与游标无 `close()`，无 `try/finally` 或 `with` 上下文。
  - 危害：连接句柄泄漏，长期运行导致句柄耗尽。
  - 修改建议：使用 `with sqlite3.connect(...) as conn:` 并在异常路径确保释放。
- 位置：`sqlite3.connect("test.db")` 及无异常捕获
  - 问题：数据库路径硬编码、未捕获 `sqlite3.Error`。
  - 危害：文件权限/路径可被替换；异常直接抛出导致信息泄露与程序崩溃。
  - 修改建议：使用受控路径与最小权限，捕获并脱敏处理异常。

【补充说明】本段代码的核心风险为 SQL 注入，必须优先修复；连接未释放与输入校验缺失为次要风险。

【性能评审结论】性能等级：**一般**

【性能问题清单】
- 位置：`conn = sqlite3.connect("test.db")`
  - 问题：每次执行均重新建立连接，无连接复用/连接池。
  - 性能损耗原因：连接建立涉及文件打开与初始化开销，被高频调用时放大。
  - 优化建议：若为常驻服务，复用连接或使用连接池；脚本场景可用 `with` 确保及时释放。
- 位置：`sql = "select * from user where name=..."`
  - 问题：`select *` 查询全部列。
  - 性能损耗原因：多余列数据传输与内存占用。
  - 优化建议：只查所需列，如 `select id, name from ...`。
- 位置：`conn` / `cursor` 未关闭
  - 问题：资源未释放。
  - 性能损耗原因：句柄与内存长期占用，可能触发连接数上限。
  - 优化建议：使用上下文管理器或 `finally` 释放。

  - 问题：无法确认 `name` 列是否有索引。
