# performance-review · Prompt 迭代说明（v1 → final）

## v1 的问题
- "帮我找找跑得慢的原因"是聊天式指令，输出偏口语化建议清单；
- 没有量化视角（复杂度、IO 次数），容易泛泛而谈"可以优化"；
- 无固定输出格式。

## final 版的修改点与理由
1. **限定性能视角**：只从性能、时间复杂度、资源开销角度审查——避免越界到架构/安全；
2. **枚举评估维度**：时间复杂度、循环冗余、内存占用、IO 频繁调用、不必要计算、低效算法；
3. **强制解释"性能损耗原因"**：不只说"这里慢"，还要说清开销如何随规模放大——这是后续冲突分析中"性能主张"能与其他维度正面交锋的关键；
4. **固定输出结构**：【性能评审结论】性能等级（优/良/一般/较差）+【性能问题清单】（位置/问题/性能损耗原因/优化建议）。
