# architecture-review · Prompt 迭代说明（v1 → final）

## v1 的问题
- "看看模块划分合不合理"过于笼统，对小代码片段模型倾向于回答"片段谈不上架构"，输出不稳定；
- 缺少可操作的架构评估维度；
- 无结构化输出。

## final 版的修改点与理由
1. **明确架构视角**：项目架构、模块职责、耦合内聚、依赖设计、可扩展性——并把"对单文件/片段如何谈架构"落在维度定义里；
2. **枚举评估维度**：模块划分、耦合度、职责单一、依赖倒置、扩展性、复用性、异常分层；
3. **要求写"架构层面影响"**：每个问题都要说清对上层的影响，而不是仅描述代码现象——这使架构意见能与其他维度的主张形成可讨论的权衡关系；
4. **固定输出结构**：【架构评审结论】架构等级（优秀/合理/有缺陷/较差）+【架构问题清单】（位置/问题/架构层面影响/重构建议）。

## 迭代效果
对测试样例输出 8 项结构问题（零分层、依赖倒置缺失、资源生命周期悬浮等）并给出端口/适配器重构建议，见 `run_log/skill_architecture_test.md`。
