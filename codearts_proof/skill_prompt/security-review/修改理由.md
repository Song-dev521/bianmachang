# security-review · Prompt 迭代说明（v1 → final）

## v1 的问题
- 只有一句"检查安全隐患"，没有限定评审边界，模型容易顺带评论性能、命名等无关维度；
- 没有输出格式约束，每次输出的结构都不一样，无法被冲突汇总 Skill 稳定对接；
- 没有风险等级定义，结论无法横向比较。

## final 版的修改点与理由
1. **明确单一职责**："只从安全角度审查代码"——保证与其他 3 个评审 Skill 的隔离性，分歧才是真实的；
2. **枚举评估维度**：注入风险、敏感信息泄露、权限控制、不安全函数、异常捕获缺失、依赖安全风险——降低漏评；
3. **强制固定输出结构**：【安全评审结论】风险等级（高/中/低/无风险）+【风险点清单】（位置/问题/危害/修改建议）+【补充说明】——结构化输出是四份报告能被汇总 Skill 机器化比对的前提；
4. **禁止闲聊与追问**：保证输出纯净、可复现。

## 迭代效果
final 版在测试中对含 SQL 注入样例稳定输出 9 项风险（含 CWE 编号、优先级分级），见 `../../run_log/skill_security_test.md`。
