# conflict-summary · Prompt 迭代说明（v1 → final）【项目核心】

## v1 的问题（方向性偏差）
v1 把"冲突"理解成了 **git 合并冲突**（"帮我看一下当前的冲突代码，梳理两边改了什么"）——与项目目标完全不符。这版 Prompt 是真实的试错记录：最初对"冲突消解"的定义就没有对齐。

## final 版的修改点与理由
1. **重新定义角色**：从"合并冲突处理"改为"软件工程权衡分析师"——收集安全、性能、架构、规范四份独立评审报告，识别**评审视角之间的观点冲突**；
2. **写入核心规则**：
   - 不简单复述四份报告，优先抓取【评审意见矛盾点】（一个维度建议做 A 优化，另一个维度指出 A 有副作用）；
   - 区分三类内容：共识、真实冲突、无关建议；
   - **客观中立，不单方面判定哪个评审是对的，只把权衡利弊交给使用者判断**——这一条是"本项目不输出标准答案、面向教学"这一产品理念在工程上的直接落地；
3. **固定输出结构**：【汇总总览】（四方结论）+ ✅【多方共识项】+ ⚖️【权衡冲突项（核心）】（冲突描述/各视角倾向/工程权衡说明）+ 📌【综合建议（教学导向）】（多条可选方案，每条写明取舍代价）。

## 迭代效果
- 对含缺陷样例：识别出"语义一致优先 vs 契约兼容优先"等 4 组冲突、4 套带代价的方案，见 `run_log/skill_conflict-summary_test.md`；
- 对"循环内反复开关数据库连接"样例：输出安全优先/性能优先/架构优先/分阶段演进 4 套互斥方案，见 `testcase/case_conflict.py.png`。
